Query Diagnosis & Query Planner:
--------------------------------
explain(): To understand how MongoDB will execute your queries. It has 3 values:
1. queryPlanner -> Show summary for executed query + Winning plan

2. executionStats -> Show detailed summary for executed query + Winning plan + possibly Rejected plans
Ex: db.customers.explain("executionStats").find({name:"Max"})

3. allPlansExecution -> Show detailed summary for executed query + Winning plan + Winning plan Decision process
Ex: db.customers.explain("allPlansExecution").find({name:"Max",age:30})

Covered query:
--------------
A covered query is a query that can be satisfied entirely using an index and does not have to examine any documents. An index covers a query when all of the following apply: all the fields in the query are part of an index, and all the fields returned in the results are in the same index. 

db.customers.insertMany([{name:"Max", age:29, salary:2000},{name:"Manu", age:30, salary:4000}] )
db.customers.createIndex({name:1})
db.customers.explain("executionStats").find({name:"Max"})
db.customers.explain("executionStats").find({name:"Max"},{_id:0,name:1})

Rejecting Plans:
----------------
db.customers.createIndex({age:1, name:1})
db.customers.explain().find({name:"Max",age:30})

How MongoDB figure out which plan is better plan?
-------------------------------------------------
Winning plans:
--------------
--> Lets consider, if we have 100 documents and have 3 approaches
--> It looks for the approach that finds 100 docs first and it will caches that winning plan(that satisfies the query we sent and with the fields we are looking for and values of fields we are looking for)
--> This cache is cleared after certain amount of inserts or index is rebuilt or other indexes are added/removed or MongoDB server is restarted

Multi-key Indexes:
------------------
--> works as a normal indexes but stored as different

db.contacts.insertOne({name:"Max", hobbies:["Cooking", "Sports"], addresses: [{street:"Main Street"}, {street: "Second Street"}]})

db.contacts.findOne()

db.contacts.createIndex({hobbies:1})

db.contacts.explain("executionStats").find({hobbies:"Sports"})

--> Indexes holds the documents, but not the fields of the documents
    
db.contacts.createIndex({addresses:1})

db.contacts.explain("executionStats").find({"addresses.street":"Main Street"}) //gives COLLSCAN

--> Multi-key holds both documents and its fields

db.contacts.createIndex({"addresses.street":1})

db.contacts.explain("executionStats").find({"addresses.street":"Main Street"}) //gives IXSCAN

db.contacts.createIndex({name:1, hobbies:1}) // creates index

db.contacts.createIndex({addresses:1, hobbies:1}) //gives error - "CannotIndexParallelArrays"

$meta 
-----
The $meta projection operator returns for each matching document the metadata (e.g. "textScore") associated with the query
textScore:
Returns the score associated with the corresponding $text query for each matching document. The text score signifies how well the document matched the search term or terms. If not used in conjunction with a $text query, returns a score of 0.

We can add indexes in 2 ways:
1. Foreground
    -- Collection is locked during index creation
    -- Faster
   EX: db.ratings.createIndex({age:1})
  
2. Background
    -- Collection is accessible during index creation
    -- Slower

Aggregation Framework:-
----------------------

--> To retrieve data efficiently & in a structured way.
--> You can use it to retrieve the data in exactly format you need in your app.
--> Aggregation is a pipeline of steps that runs on the data that is retrieved from your collection and then gives you the output in the form you needed.

Collection -> {$match} -> {$sort} -> {$group} -> {$project} -> o/p(list of docs.)

$match:
-------
--> It is like filter method 
db.persons.aggregate([ { $match: {gender:"female"}} ]).pretty()

$group:
-------
--> groups stage allows you to group data by certain field or multiple fields
--> <accumulator> operators: avg, first, last, max, min, push, sum, addToSet, stdDevPop, stdDevSamp

db.persons.aggregate([ { $match: {gender:"female"}} , { $group:{_id:{state:"$location.state"},totalPersons: {$sum:1}}}]).pretty()

Verification:
-------------
db.persons.find({gender:"female", "location.state":"ankara"}).count()

$sort:
------
db.persons.aggregate([ { $match: { gender : "female" }}, { $group: { _id : { state : "$location.state" }, totalPersons : {$sum : 1} } }, {$sort : { totalPersons : -1 } } ]).pretty()

db.persons.aggregate([ { $match : { "dob.age" : { $gt : 50 } } }, { $group : { _id : { gender : "$gender" }, numPersons : { $sum : 1 }, avgAge : { $avg : "$dob.age" } } },  { $sort : { numPersons : -1}} ]).pretty()

$project:
---------
--> same as projection in find()
--> project does not group multiple documents together, it just transforms every single document

db.persons.aggregate([{$project: {_id:0, gender:1, fullName: { $concat: ["$name.first", " ", "$name.last"]}}}]).pretty()

db.persons.aggregate([{$project: {_id:0, gender:1, fullName: { $concat: ["Hello ", "$name.first", " ","$name.last"]}}}]).pretty()

db.persons.aggregate([{$project: {_id:0, gender:1, fullName: { $concat: [{$toUpper:"$name.first"}, " ", {$toUpper:"$name.last"}]}}}]).pretty()

db.persons.aggregate([ { $project : { _id : 0, gender : 1, fullName : { $concat : [ { $toUpper : { $substrCP : ['$name.first', 0, 1]}}, ' ', { $toUpper : { $substrCP : ['$name.last', 0, 1]}}]}}}]).pretty()

db.persons.aggregate([ { $project : { _id : 0 , gender : 1, fullName : { $concat : [{ $toUpper : { $substrCP : ['$name.first', 0 ,1]}}, {$substrCP : ['$name.first' , 1, { $subtract: [{ $strLenCP : 'name.first'}, 1]}]}, ' ', { $toUpper : { $substrCP: ['$name.last', 0 , 1]}}, { $substrCP : ['$name.last', 1, { $subtract: [{ $strLenCP: 'name.last'}, 1]}]} ]}}} ])
